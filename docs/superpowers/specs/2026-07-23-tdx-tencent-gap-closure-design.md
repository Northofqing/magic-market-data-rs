# TDX 与 Tencent 能力缺口收敛设计

状态：按用户“无需确认、直接完成”的持续授权采用本设计。

## 1. 目标

本阶段只处理 `magic-tdx-rs` 和 `magic-tencent-rs`。目标不是把无法证明的网页
字段标成支持，而是把每项缺口收敛为以下两种可审计结果之一：

1. 有真实协议响应、固定夹具、严格解析和在线探针的已支持能力；
2. 有具体缺失字段或协议证据说明的 `Unsupported`。

不得从报价、五档或逐笔推导并冒充来源资金流、集合竞价、财务或公司行为数据。

## 2. 已选方案

采用“按来源原生端点分能力接入”：

- TDX 继续使用现有二进制协议和服务器池，先验证北京市场编码与报价原始时间字段；
- Tencent 快照、K 线、分时和逐笔使用各自独立 HTTPS 端点、响应上限和解析器；
- Provider 能力位只有在相应统一契约可直接调用且真实探针通过后才变为 `true`；
- 端点不存在、字段不足或单位不能核验时维持 `false`，方法返回带原因的
  `Unsupported`。

拒绝两个备选方案：

- 从逐笔成交金额按阈值推导主力/大单资金流：分类规则不是来源合同；
- 抓取登录客户端私有流量：没有稳定协议、版本合同和程序化读取授权。

## 3. TDX 范围

### 3.1 北京市场

在线探针分别用候选市场编码请求同一只有效北交所证券，并校验返回市场、代码、价格
和记录数。只有一个候选编码稳定返回匹配记录时，才将 `Exchange::Beijing` 映射到该
编码，并为 Quote、K 线、分时、逐笔和证券元数据复用同一映射。无唯一结果则继续
`Unsupported`，探针打印每个候选的原始结果。

### 3.2 行情源时间

`SecurityQuote::reversed_bytes0` 继续原样保留。只有在多个在线样本中能证明其编码规则、
日期归属和时区，且严格解码器能拒绝越界值时，才写入 `servertime` 和标准
`source_at`。仅有“数值随时间变化”的相关性不足以升级为来源时间。

### 3.3 资金流与集合竞价

当前 TDX 报价包只有买卖累计量和五档，不能填满统一 `MoneyFlow` 的主力、超大、大、
中、小五个金额字段，也没有统一 `AuctionSnapshot` 所需的匹配金额、未匹配买卖量和
量比。本阶段保留两个能力为 `false`，补齐失败测试和文档中的字段级原因。不得用
`b_vol - s_vol` 或五档差值伪造资金流，不得把普通快照冒充集合竞价。

## 4. Tencent 范围

### 4.1 北京市场基础行情

快照端点已经真实返回 `bj920118`，载荷市场码为 `62`。增加 `bj` 符号编码和市场码
校验，使北京股票 Quote 与五档盘口进入现有严格批次合同；指数、基金、债券仍不因此
自动开放。

### 4.2 历史 K 线

接入 `web.ifzq.gtimg.cn/appstock/app/fqkline/get`。只支持端点直接返回并能验证的周期
与复权组合；请求条数、响应体和记录数均受限。每根记录严格校验日期、OHLC 关系、
价格、累计量、排序和重复，来源日期写入记录证据。没有成交额的响应保留 `None`。

### 4.3 分时

在 `magic-market-core` 增加 provider-neutral `MinutePoint`、
`MinuteDataRequest`/`MinuteData` 契约。Tencent 当前分时端点和历史按日端点返回累计
成交量/成交额；解析器校验交易时刻、单调累计量/额、午休边界和请求日期。TDX 同时
实现该统一契约，避免能力矩阵中的 `minute=true` 只有布尔位而不可调用。

### 4.4 逐笔成交

接入 `stock.gtimg.cn/data/index.php?appn=detail&action=data` 当前交易日分页端点。
字段按序号、时间、价格、变动、成交量、成交额、B/S/M 方向解析；校验金额与
价量数量级、页序、重复和请求上限。`B/S/M` 分别映射 Buy/Sell/Neutral。若端点不
提供可验证历史日期选择，带日期请求明确 `Unsupported`。

### 4.5 证券元数据及剩余能力

Tencent 快照可直接提供名称和 ST 名称证据，板块只按交易所/代码显式标记为派生；
上市日期、规则版本和来源价格限制缺失时返回部分 `SecurityMetadata`，状态为
`Unavailable` 且批次质量列出字段缺口。

`fundamentals`、`corporate_actions`、`blocks`、`money_flow` 和 `auction` 在找到
可重复、字段完整的来源端点前继续为 `false`。实测返回 `v_pv_none_match` 的旧
`ff_` 资金流入口不作为支持证据。

## 5. 结构

`magic-tencent-rs` 从单个大文件拆为：

- `client.rs`：端点配置、请求边界和能力入口；
- `transport.rs`：HTTPS-only、重定向拒绝、超时和响应上限；
- `symbol.rs`：沪深京股票符号映射；
- `snapshot.rs`：Quote、五档和部分证券元数据；
- `bars.rs`：K 线请求与 JSON 解析；
- `minute.rs`：当前/历史分时解析；
- `trades.rs`：当前逐笔分页解析；
- `time.rs`：中国市场日期时间的严格格式化与校验。

公开 `TencentClient` 和错误类型保持 crate 顶层可用，内部解析器只对 crate 测试开放。

## 6. 错误、限流和并发

- 所有端点必须为 HTTPS，拒绝重定向；
- 每种响应使用独立最大字节数，所有计数先检查再分配；
- K 线、分时和逐笔请求设置硬上限，分页有最大页数；
- 多证券快照保持请求顺序和精确基数；
- 无数据、协议错误、限额、历史不支持分别返回不同错误信息；
- 不自动切换 TDX/Tencent，不缓存陈旧响应，不吞掉部分页失败；
- 现有负载探针扩展到新能力，但并发和总请求仍受硬上限约束。

## 7. 验收

确定性验收包括 fixture、畸形输入、超限、乱序、重复、日期、OHLC、累计量、分页和
Unsupported 测试。在线验收至少覆盖：

- 华电辽能 `600396.SH`；
- 平安银行 `000001.SZ`；
- 一只在线可用的北京股票；
- Tencent Quote/五档/K线/当前与历史分时/当前逐笔；
- TDX 北京候选编码、Quote/K线/分时/逐笔；
- 所有仍不支持能力的明确输出。

最终必须通过格式化、workspace tests、strict Clippy、Rust 1.83 all-target check、
rustdoc/doctest、文档链接、合规检查和有界负载探针。在线样本只记录实测，不宣称 SLA。
