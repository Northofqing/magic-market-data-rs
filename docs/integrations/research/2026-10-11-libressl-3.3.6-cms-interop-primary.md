## Target format and source support

Target: attached SignedData, SHA256/RSA3072 PKCS#1 signature, `id-data` bytes containing the complete DER EnvelopedData; inner AES256-CBC and one RSA-OAEP recipient with SHA256 hash/MGF1 and empty label. Nested encapsulations and signing previously encapsulated bytes are standard CMS; `id-data` may carry arbitrary octets. [RFC 5652 §§1,4,5,6](https://www.rfc-editor.org/info/rfc5652/).

| Requirement | Exact upstream evidence; not a binary result |
| --- | --- |
| `-binary`, `-inform DER`, `-verify`, `-decrypt`, `-nointern`, `-certfile`, `-CAfile`, `-CApath` | Tagged `cms.c` argument parsing and DER decoder; binary avoids text conversion. |
| Attached outer / binary output | Verify/decrypt clear the creation-only detached flag; verifier reads contained content. `-outform DER` does not re-encode verify/decrypt output: it is extracted bytes. |
| `-keyopt rsa_oaep_md:sha256` | RSA string control exists, but CMS key options are applied during encryption/signing, **not decrypt**. Decryption must use encoded OAEP parameters, not an assumed CLI override. |

[3.3.6 CMS CLI source, relevant blocks 150–489,607–770,778–803,873–948](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/usr.bin/openssl/cms.c), [versioned CMS man section](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/usr.bin/openssl/openssl.1), [RSA control 660–662](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/lib/libcrypto/rsa/rsa_pmeth.c).

`rsa_cms_decrypt` (892–960) decodes `RSA_OAEP_PARAMS`, resolves `hashFunc` and nested MGF1 digest independently, then sets OAEP padding/both digests/label. Missing digest parameters default to SHA1, so **check explicit SHA256 parameters; never fallback**. The EVP decrypt path calls the OAEP/MGF1 padding checker. This is concrete SHA256-capable code, not an inference from a modern manual. [RSA ASN.1/decrypt source](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/lib/libcrypto/rsa/rsa_ameth.c), [RSA decrypt 350–372](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/lib/libcrypto/rsa/rsa_pmeth.c).

CMS decrypt resolves the encoded content cipher OID and ASN.1 IV. The tagged CLI registers AES256-CBC; actual compiled features and interoperability still require a nonsecret sample. [CMS cipher initialization 66–122](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/lib/libcrypto/cms/cms_enc.c).

## Trust and ordering — no verification bypass

`-nointern` confines signer lookup to external certificates; it does not impose a DER pin, exactly one signer, algorithm allowlist, or remove embedded untrusted chain certificates. External signer matching uses issuer/serial or key identifier. Pin the single supplied sender certificate before use and independently enforce the complete profile/cardinality. [Signer lookup/comparison 212–237,504–548](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/lib/libcrypto/cms/cms_sd.c), [versioned verify contract](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/lib/libcrypto/man/CMS_verify.3).

`setup_verify` loads defaults separately when either CAfile or CApath is absent. A source-supported **nonsecret test design** uses a CAfile containing only the exact synthetic self-signed sender and an explicit dedicated empty 0700 CApath. An empty-string CApath is invalid. Supplying both avoids these two default-loader branches; it is not proof of all Apple file accesses or real identity trust. [Store setup 1097–1131](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/usr.bin/openssl/apps.c), [directory handling 115–136,192 onward](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/lib/libcrypto/x509/by_dir.c).

Default certificate purpose is S/MIME signing. KU/EKU rejection is conditional on the extension existing; a synthetic certificate with neither is **not rejected solely for their absence**. Dates, chain and mathematical signatures must still pass. This supports trying the ordinary no-bypass path, not predicting its outcome or accepting a real certificate profile. Do not substitute `-purpose any`, `-noverify`, `-nosigs`, `-no_attr_verify` or `-no_content_verify`. [Purpose/default verification](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/lib/libcrypto/cms/cms_smime.c), [purpose predicates 66–69,680–717](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/lib/libcrypto/x509/x509_purp.c).

Verifier copies content to output **before** its final content-digest check (423–438). Here that output is only inner ciphertext, but it remains unauthenticated until verified exit 0. **No verify→decrypt pipe**: finish verification and strict profile checks first, then decrypt held ciphertext to a private destination; partial plaintext is not accepted on failed decrypt. [Verify/decrypt sequencing](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/lib/libcrypto/cms/cms_smime.c).

## Seed/config paths for future synthetic generation

Tagged `genrsa` has no seed-file call; tagged `req` likewise has no `RAND_*` file call. RAND bytes use `arc4random_buf`; `RAND_file_name` returns `/dev/urandom`, not HOME/.rnd. `RAND_write_file` still writes its explicit argument, so this is not a blanket no-files assertion. [Complete genrsa source](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/usr.bin/openssl/genrsa.c), [RAND implementation](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/lib/libcrypto/rand/rand_lib.c), [RAND file API](https://raw.githubusercontent.com/libressl/openbsd/libressl-v3.3.6/src/lib/libcrypto/rand/randfile.c).
