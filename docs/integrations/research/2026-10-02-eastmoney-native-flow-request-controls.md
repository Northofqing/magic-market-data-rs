# Eastmoney native flow request controls (2026-10-02)

## Scope and result

This bounded follow-up compares the current first-party Eastmoney page constructors for one Shenzhen equity's daily five-tier net flows and the industry board-flow table with production source revision `9963887408c65bbcb9db0ccfd821190aabe64b8d`. It does not change code, admission, dependencies, TLS, proxy, deployment, or credentials. The `autonomous-long-task` skill requested by repository instructions is absent from the available catalog and checkout; this background task used the available `research` workflow.

**Request drift is real.** The current stock page constructs daily requests on `push2his.eastmoney.com/api/qt/stock/fflow/daykline/get` with a public page-embedded `ut` value and JSONP `cb`; the repository uses `push2delay.eastmoney.com/api/qt/stock/fflow/kline/get` without either. The current industry page still constructs `push2.eastmoney.com/api/qt/clist/get`, but uses industry filter `m:90 s:4` and another public `ut`; the repository uses `m:90+t:2` and omits `ut`. The URL constructor evidence is in the captured [stock script](https://data.eastmoney.com/newstatic/js/zjlx/stock.js) and [board script](https://data.eastmoney.com/newstatic/js/bkzj/list.js), with hashes below; the repository counterparts are [fund_flow.rs](../../../crates/magic-eastmoney-rs/src/fund_flow.rs) and [board_flow.rs](../../../crates/magic-eastmoney-rs/src/board_flow.rs).

One bounded stock request using the native host/path, public `ut`, and JSONP callback returned HTTP 200 and an `rc=0` body with `code=300005`, `market=0`, and two dated rows. This is **real JSONP response evidence for that one request**, not proof of stable production service, plain JSON compatibility, or a causal explanation of prior TLS closures. The native industry request still closed before HTTP status in one probe, so no live industry JSON or schema equivalence is established.

## Decision boundary

The stock page reveals a concrete alternate first-party host/path and a single successful identity-bound response, worth a formal Gate A design and repeated bounded admission checks if the production daily contract is to change. It is **not** a drop-in fix: the observed response is JSONP, the current parser expects JSON, and source reliability and returned date coverage are unverified. The industry's public filter and `ut` differ from production, but its native request still fails before status, so a BoardFlows change lacks live response evidence. A pre-status closure remains an explicit transport failure; source time and provenance cannot be fabricated. Changes to provider endpoint/filter/response handling require the documented [engineering gates](../../ENGINEERING_RULES.md), [BR-009/010](../../business_rules.md), and [HTTP dependency registry](../http-transports.tsv); this note makes no production admission claim.
